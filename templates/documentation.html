Introduction

LiteLLM Helper v3 is a web-based configuration generator for LiteLLM proxy that helps you manage LLM providers, API keys, models, key rotation, and aggregated model configurations.

This tool simplifies LiteLLM configuration by providing one UI for provider setup, model definitions, routing, and export.

Quick Start Guide
  1. Set Password: Configure LITELLM_HELPER_PASSWORD in your .env file.
  2. Add Providers: Go to Providers and add Groq, OpenRouter, Google, etc.
  3. Add API Keys: Add one or more keys per provider in API Keys.
  4. Configure Models: Define model limits, skills, timeout, and size in Models.
  5. Create Aggregations: Pool models under one shared name in Aggregated Models.
  6. Export: Generate proxy configuration in Export Config.
Features Overview
Provider Management: Add and edit API base URLs and provider metadata.
API Key Management: Keep multiple keys and toggle active/inactive states.
Model Configuration: Control per-model limits, capabilities, and skills.
Aggregated Models: Route across providers through a shared model name.
Key Rotation: Distribute requests across keys to reduce throttling risk.
Health Checks: Verify model availability from the UI.
Understanding Aggregated Models

Aggregated models let you map multiple provider models to one shared alias. This improves resiliency and gives you a larger combined key pool.

Common Benefits
  • Load balancing across providers and keys.
  • Automatic fallback when one provider has transient errors.
  • Higher total throughput by combining key quotas.
  • Vendor redundancy without changing client-side model names.
Model Fallback Configuration

Model fallbacks define primary-to-secondary model failover chains for LiteLLM. When requests to a primary model fail or hit rate limits, LiteLLM automatically routes the request to configured fallback models in priority order.

Configuring Fallbacks & Export Controls
  • Primary Model: The request target (individual or aggregated shared model name).
  • Fallback Target Sequence: Ordered list of fallback models tried sequentially.
  • Export Customization: In Export Config, users can toggle whether fallback rules and aggregation rules are included in the generated LiteLLM configuration file.
Key Rotation Strategies Explained

Key rotation strategy decides how requests are distributed across active keys. Choosing the right strategy depends on your quotas, reliability needs, and cost profile.

Strategy How It Works Pros Cons Best Use
Round Robin Requests are sent to keys in fixed sequence: key1, key2, key3, then repeat. Simple, fair distribution, predictable key usage, easy to debug. Does not react to temporary failures or hot keys unless combined with cooldown/failure rules. Default choice when keys are similar and stable.
Least Busy Prefers keys with lower current load or fewer recent requests. Can reduce burst throttling and smooth spikes. Needs reliable load tracking; behavior can be less predictable; higher implementation complexity. High-traffic setups with uneven request patterns.
Random Picks a random active key for each request. Very simple and avoids strict sequence hot-spots. Can be uneven over short windows; harder to reason about per-key usage. Small deployments where strict fairness is not required.
Failover Priority Uses a preferred key/key set first, then falls back when failures occur. Strong control over preferred providers or paid keys. Primary key can hit limits quickly; backups may stay mostly unused. When you have a premium primary key and backup keys.
Recommendation for Free-Tier Keys

Best default: Round Robin + cooldown + retry.

  • Why: Free-tier keys usually have tight RPM/TPM quotas. Round robin spreads requests evenly, reducing the chance of burning a single key too quickly.
  • Cooldown: If a key returns rate-limit errors, temporarily skip it for a short period (for example 30 to 120 seconds).
  • Retries: Keep retries low (for example 1 to 2) to avoid retry storms that consume limited quotas.
  • Allowed fails: Mark noisy keys inactive faster to protect overall success rate.
Suggested Baseline for Free Tier
  • Routing strategy: round_robin
  • Key rotation strategy: round_robin
  • Cooldown time: 60 seconds
  • Allowed fails: 2
  • Retries: 1
