How It Works
  • Virtual Aliases: When a primary model is assigned to a task, a duplicate entry of that model is injected into the LiteLLM Config with the name of the Virtual Alias.
  • Native Fallbacks: If a fallback model is assigned, it is injected as hermes-task-fallback. LiteLLM is automatically configured to route traffic to the fallback model if the primary model fails or rate limits. Hermes remains completely unaware of any failures!
  • Seamless Integration: Configure Hermes to use hermes-vision or hermes-mcp as the target model. LiteLLM will dynamically route it to whatever backend is selected here.
  • No Restarts: Changing the target model here and syncing to live allows Hermes to instantly switch models without requiring any configuration edits on its side.
